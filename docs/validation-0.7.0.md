# 0.7.0 大型歌曲整理、视图密度与音色映射验收

环境：Windows 11 x64、Electron 44.8.0、Node 24.19.0；保留 React / TypeScript 和工程 schema 2，无新增运行时依赖。

## 功能与容量

智能整理的旧 64 组／768 Pattern 预算改为与工程相同的 256 轨道、1,024 Pattern、10,000 引用；分析通道上限从 2,048 提升到 65,536。整理摘要不再误用 100,000 音符限制，与百万音符工程容量对齐。单 Pattern 500,000、工程总音符 1,000,000、原布局备份 32 MiB、工程文件 96 MiB 的边界继续校验。

独立声部过多时，按音色与音区优先共享轨道，源图层仍独立；短乐句超过输出预算时合并相邻乐句。所有音符、时间、力度、声像、微调和原图层语义保留，报告说明采用的容量策略。这是初步结构整理，不宣称每个分组都等同人工认定的音乐声部。

Playlist 行高 24–128px，NBS 图层 20–96px，钢琴行高 12–48px。改变行高尽量保留顶部可见行；输入支持自然键入多位数，离开输入框时规范范围。Ctrl+滚轮在编辑区内以鼠标处时间为锚点缩放，阻止浏览器页面缩放；普通滚轮保留滚动行为，小窗口工具栏可横向滚动。

自定义音色映射位于“添加 → 自定义音色与映射…”、音频资源栏音符按钮，以及资源设置中的自定义乐器区域。原始音符、原音色定义和音频路径保留，替换绑定可撤销、重置和随工程保存。播放与 NBS 导出使用相同调音补偿，极端调音通过 NBS 微调表示，不能表示时明确报错。目标必须存在、可播放且没有映射，禁止悬空和循环。建议参考本地 notebot SmartAssignment.java 的名称、音域、重复节奏和同时发声证据，需要用户点击应用。

已映射且没有其他未映射乐器依赖的缺失原音频不会阻止导出资源包；提示省略原因，实际自定义目标音频保留。只用内置目标且没有外部资源时说明无需 ZIP。工程重开不弹出音频目录选择。

## 回归与独立复核

完整串行测试：30 个测试文件、206 项测试全部通过；TypeScript 严格未使用检查和生产构建通过。浏览器组件测试覆盖行高点击位置、自然输入、缩放锚点、边界、普通滚动、手势取消、紧凑工具栏和末端行保持。

独立复核发现并修正图层复制导致的工程膨胀：1,200 图层／6,400 音符合成输入，800 个乐句原本生成 120,934,318 字节 JSON，无法保存；现在各乐句只保存实际使用图层，保留 sourceIndex，工程编码为 2,459,853 字节，可重开，音乐与播放事件完全一致。新增测试先复现失败再验证修正。复核结束无未解决 P1/P2。

源码候选与最终 ZIP 实际解压 EXE 各通过 73 项桌面操作，包含原有编辑、读写、子窗口、快捷键、片段采样及 PAT 目标，以及新增映射管理、实际试听、绑定保存重开、原生 Ctrl+滚轮与行高。最终运行包 ASAR 的 22 个编译文件与本地生产输出逐字节一致，解压验证副本与保留运行目录的 ASAR SHA-256 一致。

## 歌曲库

用户指定目录递归包含 112 首歌曲。旧智能整理成功 98 首，14 首因声部预算退回原布局；改进后完整初测 112 首均可整理，精确音乐事件、播放事件、NBS 再导出及工程结构校验通过。最大歌曲 265,495 音符，整理约 10.7 秒，原布局备份 30,915,170 字节。实际桌面候选完成全部 112 首智能导入，以及最大歌曲全选、适应选区、工程保存重开。

最终图层修正后的完整分析额外调用 encodeProject：112/112 智能整理、音乐事件、播放事件、NBS 导出对照、工程结构及实际可保存检查全部通过。最大工程 66,933,271 字节，最大曲最终整理耗时 10.527 秒。最终 JSON 与运行包实测记录归档到 verification。比较的是导入后可表示的音乐数据；外部采样不齐时不宣称真实音频资源均存在。112 个原始歌曲 SHA-256 与上轮只读兼容测试一致，未修改用户歌曲。

最终 ZIP 实际解压 EXE 也完成 112/112 首智能导入，所有歌曲都选择智能整理，并通过最大 265,495 音符歌曲的全选、适应选区、保存和重开。无渲染异常。
