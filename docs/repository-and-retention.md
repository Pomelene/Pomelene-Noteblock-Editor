# 仓库与本地产物管理

代码仓库：https://github.com/Pomelene/NoteBlock-Editor ，私有可见。

## 代码备份

- `main` 是当前工程的默认分支，保留已有完整提交历史。
- `v0.3.0`、`v0.4.0`、`v0.5.0`、`v0.6.0`、`v0.6.1` 标记相应产品源码；维护文档可以在版本标签之后继续提交。
- `legacy/desktop-0.2` 保留重构前 desktop 工程的 Git 历史。
- 已有开发分支保留。完成后续版本时提交并推送代码及对应版本标签，再核对远端提交，避免只有本地 Git 记录。
- 远端只存源码、构建配置、依赖锁文件和项目资源，不将 node_modules、构建输出、测试临时文件或 Electron 运行目录提交进 Git。
- `.env`、私钥文件等本地配置不应提交；身份验证交给 Git Credential Manager，不把令牌写入代码、远端 URL 或脚本。

## 本地空间规则

用户要求允许保留多版本源码，但尽量只留一个版本的可运行应用。

- 保留当前版本的完整 `win-unpacked` 目录，作为本地运行入口。
- 新版本完成验证后，删除上一版本的 `win-unpacked`、临时解压验证目录，以及无需分发的 Windows ZIP。
- 各版本 `*-source.zip`、必要验收记录、哈希和源码 Git 历史继续保留。
- 需要重新分发运行版时，从当前源码重新构建、打包；分发结束后可以清理冗余压缩包。
- 清理前核对绝对路径，保护源码、用户工程、当前运行版本和仍被引用的依赖目录；记录清理项、释放空间和源码哈希验证结果。

截至 2026-10-18，本地应用保留 0.6.1；0.2.0、0.2.1、0.3.0、0.4.0、0.5.0、0.6.0 的运行副本已经清理，源码归档继续保留。最新应用的 Windows ZIP 也作为冗余分发副本清理，只保留可直接运行的解压目录。

开发机 `desktop-next/node_modules` 仍通过目录联接引用 `desktop/node_modules`。该目录包含当前开发依赖和构建所需 Electron runtime，不能因为 desktop 是旧工程就整目录删除。旧工程源码保留，旧的 release/out/test-results 可以清理。

具体清理记录位于开发工作区的 `deliverables/cleanup-2026-10-18.json 和 deliverables/cleanup-2026-10-18-0.6.json`。历史验收记录里的旧运行路径和 Windows ZIP 哈希属于当时的发布证据，不表示这些大文件仍保留在本机。
