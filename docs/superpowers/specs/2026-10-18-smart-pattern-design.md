# 智能 Pattern 整理（Beta）设计

用户已授权在 NBS 导入界面加入可选的智能整理，并要求搜索实践经验、实现首版算法、保留迭代空间。基于此前已确认的“声部分组、可变长度乐句、严格重复复用、变奏独立、保留原始布局”实施，不再追加通用确认。

## 交互

选择 NBS 后显示真正的应用内导入对话框，名称、音符/图层/BPM/拍号、整理前后 Pattern/引用/声部数量和建议分组可预览。复选框原文为“智能 Pattern 整理（Beta）”，默认选中，可关闭回到原始整曲 Pattern。取消不替换当前工程。工程 JSON 正常打开，不重新整理。所有入口（按钮、Ctrl+O、原生菜单）共用同一导入决策；只向发起窗口发送带唯一 token 的预览。关闭发起窗口或主窗时取消等待，不让 busy 锁悬挂。

整理结果保存版本化报告和原始 patterns/clips/tracks 的 JSON 字符串备份，避免每次撤销深拷贝第二套音符对象。编辑菜单提供“恢复原始导入布局”，需说明会替换当前编排和音符、可撤销；乐器音频和工程其它属性保留。文件格式仍 schema 2，可选字段向前兼容，后续算法不在重开工程时自动重跑。

## 首版算法 nbs-structure-1

独立纯数据模块：features.ts 提取源图层/乐器 lane、名字、音域/发声时间/音色证据；grouping.ts 保守合组；segmentation.ts 根据小节特征与重复序列做可变长度分段；index.ts 组装/严格去重/完整性验证/报告。参数集中在 profile.ts，可替换策略并记录版本。不引入模型下载或联网分析。

强证据是作者命名的相关层、同乐器的同步和弦分声部；不同音域且不同发声节奏的相同乐器保留分离。2/3/4 号乐器只作为低置信的打击乐线索，旋律性 Click 不按鼓组强行合并，自定义乐器不按编号猜角色。未知声部使用中性名称。图层名字/音量/声像/锁定等原始数据保留，并记录 sourceIndex。

分段以原文件拍号为参考网格，不移动音符。候选 1/2/3/4/6/8 小节；小节相位从原点保留，不删弱起或前导空白。按节奏、音级、乐器分布与密度的相邻小节变化评估边界，长无触发区作为边界证据。对候选片段的可复用频率和存储/引用开销做动态规划，鼓点可短、旋律可长，不统一切一小节。实现时选择超出预算直接回退原布局，不粗化网格，以免掩盖切句质量下降；复杂度与候选数量有上限。

重复指纹保留相对 tick、源图层、音高、乐器、力度、声像、微调；快速指纹只用于索引，真正共享源之前比较完整签名，防止哈希碰撞。近似/移调片段绝不自动合并。未找到重复也能按长乐句和强边界整理。置信度是启发式证据强弱，不宣称识别主副歌。

## 无损与尾音

保留每个原音符的全部音乐属性、重数及绝对位置。分组后的图层带原图层 sourceIndex，便于验证与导出。每个生成引用带 tailTicks（距该引用起点的原曲结束边界），使新切句不截断原本跨边界的采样尾音。改变引用长度、偏移或源 Pattern 长度时清除此标记，恢复用户主动裁剪语义。最后一个引用的长度补到原曲终点，保留尾部空白；源 Pattern 不因补白而重复。原始模式与智能模式的音频事件（含音量、声像、调音、播放窗口）和触发多重集合必须一致。

重复引用的 NBS 导出共享相同源图层设置，重叠音符仍由底层 codec 分配碰撞层，避免每个片段新增一套层导致 4096 层上限溢出。空图层原始数据保存在备份里。超出 track/pattern/clip/backup/分析预算时安全回退原布局并解释原因。

## 验收

先写失败测试：精确重复复用、力度/微调/扫弦差异不合并、同音色不同声部不乱合、和弦层组合、奇数小节/弱起/三连音、尾音窗口相等、前后留白、无音符、锁定/声像/自定义乐器、预算回退、恢复/撤销/保存重开、取消导入/陈旧token。用本机已有 NBS 歌曲做只读批量评估，不把歌曲本体打进源码。最终实际 Electron 操作复选框、取消、导入、报告、恢复、文件往返，并对解压后的 0.4.0 Windows ZIP 再验证。保留 0.3.0 发布。
