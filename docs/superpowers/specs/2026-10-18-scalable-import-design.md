# 大型歌曲整理、视图密度与音色绑定

本次需求以用户提供的 112 首 NBS 歌曲库为真实验收材料。用户希望大多数歌曲可以自动切分声部，不因过小的声部／音符限制而退回单 Pattern；大量声部时可调整横排行高；编辑窗口内 Ctrl+滚轮调整时间尺度；不支持的音色可以手动映射到已有音色，工程保存后能在自定义音色中再次修改，并参考本地 notebot 的智能分配方法提供初始建议。

保留 Electron + React 桌面应用、独立子窗口、现有快捷键和 NBS 文件兼容能力。算法只调整布局，不量化、删除、移动原音符，不凭空修复音乐。复杂歌曲采用较粗的分组／较长片段，以有限的分析和编排资源保留全部内容。原布局备份和恢复继续可用。报告必须准确说明降级策略。

实现者决定：行高统一作用于当前编辑器的所有行，默认保持现有尺寸；Ctrl+滚轮以鼠标指向的时间为缩放锚点，不影响普通滚动。音色绑定保存替换目标而非改写原音符。建议基于名称、音域和节奏统计，明确由用户应用，可重设、撤销和保存；来源音色调音与目标调音之间的差异需要在播放和导出中一致补偿。目标必须存在且可播放，不允许循环、悬空或隐式多级绑定。

验收包括递归歌曲库的整理覆盖率、音符事件／音频计划／NBS 再导出一致性；大型摘要工程保存重开；行高、滚轮、鼠标锚点、紧凑窗口、普通滚动；音色建议、手动绑定、恢复、撤销、重开、导出和错误目标拒绝。真实歌曲仅做只读测试，不收进源码仓库。交付源码与可执行文件分开，只保留一份最新可运行应用，保留历史源码归档。
