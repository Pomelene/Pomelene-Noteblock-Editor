# NBS compatibility and project v2 implementation plan

> **For agentic workers:** Use test-driven development for each domain and a fresh whole-change review after integration.

**Goal:** Correctly import, play and re-export supported NBS control events, and save self-contained projects with an explicit v2 prefix and corruption checks.

**Architecture:** Keep the NBS adapter, event timing and project container in the portable TypeScript core. Project-level control events retain raw NBS protocol fields independently of smart pattern segmentation. Electron continues to own dialogs and atomic file writes.

**Tech Stack:** Existing Electron / React / TypeScript; no new runtime dependency.

**Spec:** User approved control-structure support and v2-only project reads, then clarified that NBS compatibility is the core. Existing research: ../input-formats-and-control-events.md.

## Global constraints

- NBS classic and versions 1–6 remain input formats; v5 is the interchange export format.
- No legacy project JSON imports; the existing internal schema is distinct from the file-container version.
- Project bytes start with `PNE-PROJECT v2\n`, then little-endian uint32 payload length and CRC32, then UTF-8 JSON. Limit 96 MiB including header; reject trailing bytes, invalid UTF-8, bad length/checksum, unsupported versions and invalid references before replacing the current document.
- Embedded sample audio stays self-contained in the validated JSON payload. Existing durable atomic writes remain in use.
- No speculative multi-format adapters in this iteration. MIDI, text song formats, MuseScore and world structures are deferred.
- Known NBS controls are retained as project-level `nbsEvents`; names identify their protocol, not fixed instrument IDs. Unknown custom instruments remain instruments and preserve metadata.
- Tempo changes affect scheduling, seeking and loops. Stopper events shorten sound tails by original layer range. Visual controls are preserved and disclosed; Show Save Popup never invokes file writes.
- Shared/legacy modules must remain independent of Electron and filesystem APIs. Do not drop generation guards or cross-window playback ownership.

## Review focus

- Raw stopper bytes above normal velocity/panning ranges must survive parsing and re-export.
- Smart pattern organization must neither duplicate nor discard project-level controls.
- Seeking/looping through changing tempos must preserve audio-clock deadlines.
- Corrupt or legacy project files must leave the open document untouched.
- Functional controls must not request missing audio or acquire ordinary instrument mappings.

## Decisions

- The user-requested “v2” names the project format; product name stays Pomelene Noteblock Editor.
- Binary framing over existing JSON was selected for clear versioning, integrity, portability and easy inspection; it is not encryption or authentication.
- This plan records implementation choices within the already authorized work and does not add another approval gate.
