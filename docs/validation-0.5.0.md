# 0.5.0 片段采样与编辑交互验收

环境：Windows 11 x64、Node 24.19.0、Electron 44.8.0、150% DPI。用户要求改善连续放置、尾部裁剪和吸附，并明确“采样”是只读的可复用音乐片段。本轮沿用 0.4 工程、保留原发布、无新增运行时依赖。

## 本轮交付行为

| 类别 | 行为 |
|---|---|
| 工具 | P 绘制、B 连续笔刷、E 选择、D 连续删除；Playlist 增加 T 静音、S 滑移；菜单含真实剪切、粘贴、接续复制、取消选择及缩放适应内容 |
| 连续手势 | 快速扫过补齐位置、回扫不重复，松开一次提交，一个手势一次撤销；Esc、失焦、指针取消和换工程取消预览 |
| 片段尾部 | 明确边缘命中与调整光标，长度/补白实时反馈，短片段可拖；只改一条引用，源和其它引用保持原样 |
| 吸附 | 可见标签与磁铁图标，稳定的选项值；关闭、自动网格、直拍、三连音、小节；自动网格和实际吸附一致，Alt 自由定位，保留原有离格相位 |
| 片段采样 | Pattern 或编排选区保存只读快照，导入 NBS 片段，不替换当前工程；重复引用、裁剪、补静音、保存和导出 |
| 只读预览 | 实际音符画布、缩放、预听、原生或内部窗口；不提供可编辑音符属性，创建独立 Pattern 后编辑 |
| 历史音频 | 原有 OGG/音频/乐器资源继续兼容，移入明确命名的音频资源区域；没有把音频误当作音符片段 |

片段采样保留音符/图层快照，乐器仍引用当前工程的资源。选区保存按所选引用的可见触发窗口截取，保留间隔和末尾补白；不承诺逐音符保存智能导入的任意跨片段尾音窗口。未主动裁剪的原智能导入引用仍保留原尾音规则。

外部 NBS 片段保留 tick 并跟随宿主 BPM；原速度不同会提示。导入合并需要的乐器和可找到的音频，重映射冲突 ID，清除外部图层 sourceIndex，原子提交，可撤销。包含直接音频引用的选区不能保存为音符采样，会报明确信息并保留当前工程。

工程继续使用 schema 2 和可选 phrases 字段，新版能打开旧工程；包含新片段类型的工程需要 0.5 或更新版本。小数/三连音 tick 导出 NBS 时仍提示取整。

## 验证

- 严格 TypeScript 类型检查及 noUnusedLocals 通过。
- Vitest：18 个文件、122 项通过。新增采样不可变、独立复制/转换、选区时间跨度与静音/独奏、原始音频兼容、资源 ID 冲突、导入回滚、吸附/快速手势和实际音频引擎预听覆盖。
- 实际 Electron 新增 18 组交互流程通过；旧基础 20 组、智能导入 12 组重新通过。
- Windows ZIP 实际解压后，对解压 EXE 再运行同一套 50 组流程全部通过；asar 中 22 个构建文件与当前 out 逐文件一致，运行归档 77 项，不包含项目 src/tests/依赖树。
- 实际查看只读预览、拍值选择器、片段编排和 1000×650 紧凑窗口截图。系统对话框仅替换路径选择，IPC、磁盘读写、音频解码和鼠标/键盘使用真实实现。
- 独立审查完成，发现的两处具体问题均有复现、失败回归及修复；复核无未解决的具体 P1/P2。

新交互流程如下（scripts/phrase-interaction-smoke.cjs）：

1. 吸附选项包含自由、自动、明确拍值、三连音及随拍号小节。
2. 小于吸附步长的短源第一次放置也从正确吸附点开始。
3. 快速连续放置、回扫无重复、一次撤销及重做。
4. 右键快速跨过片段连续擦除、一次撤销。
5. Esc 和失焦取消未提交笔刷。
6. 多选时拖一条引用尾部，仅改单条；从标题边缘也可命中，源内容不变。
7. 短至 0.5 tick 的引用仍能拖尾，不误开角标菜单。
8. 打开相同工程 ID 的新文档代际，丢弃旧手势。
9. Pattern 保存只读采样、点击画布/Delete 不改数据，实际预听可用。
10. 从采样创建独立 Pattern，实际加音符不影响原采样。
11. 音符笔刷、一次撤销、三连音放置，不量化既有离格音符。
12. 只读采样连续放置及拖尾，源数据不变。
13. 片段角标菜单剪切实际点击的选区，编排选区可保存为采样。
14. T 静音和 S 滑移作用于单引用，可撤销。
15. 工程文件保存重开保留采样，实际导出为 NBS 音符。
16. 从菜单导入 NBS 片段，增加库对象，保留当前工程和编排，可撤销。
17. 原生只读预览可创建独立原生 Pattern 编辑窗口。
18. 紧凑窗口可访问吸附和转换按钮，无 renderer 异常或恢复页面。

基础回归沿用原坐标时显式选择 1/4 拍（1 tick），新增吸附模式由上面专门流程验证。没有通过放宽预期来掩盖行为变化。

## 修复证据与范围

独立审查指出，宽泛的 project:update 可被伪造载荷用于替换 phrases；现对允许修改的工程元数据进行运行时白名单校验。另一处是很短的源在粗吸附下首次笔刷可能落在原始鼠标 tick；现从吸附起点加相对位移计算。两者都先见到失败再修复。

真实菜单回归另发现“剪切”可能捕获之前选区，现明确按角标所选引用执行。音频引擎以前把所有非 Pattern 预听当作音频缓冲查找，现明确识别音频源，使只读音符采样按乐器播放。极短源跨大范围的笔刷以 10,000 个位置为预算，超限取消整个手势并提示，避免无限预览分配。

短片段预览的显示范围调整后，实际回归捕获了 150% DPI 下滚动条交替出现的布局抖动。测量发现整数 clientHeight 与小数布局尺寸互相反馈；改用 ResizeObserver 的内容尺寸向下取整，增加连续多帧几何稳定性断言，并重新通过全部交互流程。

FL 手册依据见 reference-notes.md。没有声称复刻全部 FL 菜单；切片、滑音、效果器、音频转音符和自动生成伴奏不在本轮实现范围。交付的 verification 目录提供源码和解压 EXE 的同组测试结果、截图、manifest 与哈希；Windows 和源码独立打包。
