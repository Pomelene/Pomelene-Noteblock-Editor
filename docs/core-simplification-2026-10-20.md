# 核心路径求简记录 · 2026-10-20

这是首阶段的实现与测量记录。后续快照、绘制与打包体积优化，以及已完成的真实曲库回归，见 [0.5.9 整理说明](release-0.5.9.md)。

本轮以 v0.5.8 为基线，保留现有功能及输出，优先消除重复扫描、短生命周期对象和重复机制。没有更换框架、升级工程格式或更新安装版本。

## 已完成

| 路径 | 原问题 | 调整与边界 |
| --- | --- | --- |
| 播放计划 `shared/timeline.ts` | 每个音符反复遍历乐器与采样；引用逐一查找来源 | 每次构建建立局部 Map；单音预听与批量播放共用音符计算，不使用跨工程全局索引 |
| NBS 编码 `legacy/nbs.ts` | 一个音符分配多个 1–2 字节 Buffer，再拼接 | 连续缓冲区按需扩容；仍逐项验证字段、限制 32 MiB，只返回已写区域 |
| NBS 导出 `shared/io.ts` | 每音符查找资源；每个重复引用重建相同图层映射 | 一次资源索引；每个来源只计算一次图层映射，保留原图层身份和碰撞分层规则 |
| 智能整理 `shared/smartPattern` | 自写哈希、碰撞桶再比较字符串；无效输入先后克隆两次；候选间重复边界分析 | 直接完整字符串 Map；成功时仅克隆保留数据，回退只克隆一次；边界支持度每个边界计算一次。仍执行精确音符多重集校验及预算回退，图层扩展数据仍深克隆 |
| 采样 ZIP 导入/导出 `main/files.ts` | 每个文件扫描所有采样；两套路径冲突逻辑；反复筛选乐器判断采样用途 | 路径到采样数组的索引，新增资源同步加入索引；统一冲突检查，保留大小写、Sounds 前缀、共享音频和安全路径规则 |
| 编排/Pattern 窗口 | 每帧对来源、采样、选区和拖动预览嵌套查找；播放指针变化也重算音色统计 | 基于实际数据引用复用资源和选区索引；预览用 Map 覆盖，保持绘制顺序；统计及可见力度音符按依赖复用 |
| 批量引用操作 `shared/session.ts` | 更新/移动每个引用重新查找；批量删除反复 includes | 单个事务内懒建引用索引；删除使用 Set。锁定校验、重复 ID 操作语义、事务回滚及撤销机制保留 |
| 铜号 `shared/copper.ts` | 嵌套查找采样；每次编号分配创建 240 项数组 | 局部资源索引、已存在音色集合和递增空闲编号查找，保留控制/自定义编号占用规则 |
| 兼容测试脚本 | 仍遗留不必要的 SHA256 计算 | 删除该步骤，继续按实际导入、导出及音乐内容比较结果 |

## 性能对照

命令：`node scripts/benchmark-core.cjs test-results/core-benchmark/after.json`。

同机 Node v24.19.0，固定合成工程：128 小节、32 层、128 乐器、16,384 个来源音符；重复编排八次后产生 126,976 个可播放音符。各操作预热一次、测七次，记录中位数。初始基线在修改前记录，最终值在实现及所有权检查后重测。不是所有歌曲或端到端启动速度的承诺。

| 操作 | 修改前 | 修改后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 构建播放计划 | 88.15 ms | 33.19 ms | 62% |
| NBS v6 导出 | 173.77 ms | 43.14 ms | 75% |
| 智能 Pattern 整理 | 47.27 ms | 38.94 ms | 18% |
| 超预算时返回原布局 | 34.48 ms | 9.20 ms | 73% |

原始本机测量见 `test-results/core-benchmark/before.json` 和 `after.json`；这些运行产物不纳入源码。

## 验证

- 修改前记录四组特征快照：v5/v6 导出的完整字节和警告、播放事件、智能整理结果。修改后逐项完全一致；没有用散列代替内容对比。
- 新增共享路径、大小写去重、Sounds 前缀及新增资源再次关联回归，以及整理后图层扩展数据的独立所有权检查。
- 全套 46 文件的回归：沙箱中 349/350 项通过；唯一失败是 Windows junction 创建权限，主机环境单独补跑安装文件归属的 4/4 项通过。其后补充的所有权检查及智能整理相关 39/39 项通过，总计覆盖 351 项。
- 类型检查和生产构建通过。
- 实际源码 Electron 烟雾通过：四种铜号 OGG 解码、NBS v5/v6 导出、ZIP 采样包导出。
- F 盘歌曲目录的只读批测受到沙箱访问限制，两次自动权限审核均超时，未实际执行，不能据此声称本轮已重测整个歌曲库。

## 保留与后续优先级

| 区域 | 本轮判断 | 后续可做的工作 |
| --- | --- | --- |
| NBS 读取、v2 工程验证、ZIP 安全规则 | 大部分复杂性承担兼容及异常输入处理，保留 | 对新增格式问题先加最小输入用例，避免合并分支时吞掉错误 |
| Session 撤销/快照 | 本轮只改批量引用查询；全工程克隆和 JSON 比较仍有成本 | 单独测量大工程编辑延迟及历史内存，再决定序列化复用或结构共享，不能直接删除隔离 |
| Canvas 重绘 | 减少了绘制循环内查询，仍随播放指针重绘内容 | 可进一步拆分静态内容与指针层，须验证缩放、拖动预览、窗口尺寸和命中一致性 |
| 大 React 组件 | 本轮缩短了热点路径，但 App/PatternEditor/Playlist 仍大 | 按真实职责逐步抽出纯绘制和命令处理，避免仅把同一状态机机械拆成多个文件 |
| 声部分组与分段启发式 | 保留音乐决策，只减少重复工作 | 新算法单独比较真实曲库的可编辑性、复用率和音符完整性，不与结构重构混在一起 |
| 音频异步取消、单一播放所有权、文件 generation | 保留原实现和回归约束 | 不以减少状态变量为理由省略生命周期检查 |

本轮没有打包安装器、上传 Release、改动注册表或替换 F 盘应用。开发构建与原始歌曲保持分离。
