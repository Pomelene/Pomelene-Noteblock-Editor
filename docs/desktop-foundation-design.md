# Electron 桌面工程与编辑子窗口

本轮范围是将已经认可方向的第二轮原型迁入真实桌面工程，并应用用户明确提出的布局修正。不是完整 NBS 编辑器的最终功能交付。

用户决定：Electron + React 技术栈；Windows 优先，预留跨平台；音色仅在 Pattern 编辑窗口出现；借鉴 FL 子窗口；安装 UI UX Pro Max skill。

实现选择（开发方决定）：TypeScript、electron-vite、React、Lucide、CSS 语义变量。应用代码放在 `desktop/`，参考源码、试作和分析记录保留在原目录。新建独立产品 Git 仓库和开发分支，不在参考仓库中编码。

主窗口：原生 Electron BrowserWindow，含全局 BPM、拍号、播放、Pattern 浏览器、Playlist 编排。主窗口不显示音色库。Pattern 编辑使用 React 内部可拖动、缩放、最小化和最大化的非模态子窗；可以弹出成独立原生窗口，每个 Pattern 最多一个原生窗口。关闭编辑窗口不删除内容。

Pattern 编辑器：音色栏、NBS 图层视图 / 钢琴卷帘切换、音符放置删除、选区拖动、复制剪切粘贴、撤销重做、键盘预听。保留本机 NBS 16 个原始采样和 MIDI 66 / F♯4 基准。样本资源作为本地开发资源记录来源；公开发行前另行核对素材分发安排。

状态：主进程维护唯一工程状态，以明确命令更新并向所有窗口广播修订号。渲染进程只经受限 preload API 通信。多个窗口修改同一 Pattern 的不同音符应合并到最新状态；旧快照不可覆盖新快照。一次拖动只提交一个命令。操作数据非法、目标同层同格冲突时拒绝且保留原数据。共享撤销对整个工程生效。

窗口安全：contextIsolation=true、sandbox=true、nodeIntegration=false；禁止任意导航及任意新窗口；IPC 验证所属窗口和命令参数。只加载本地打包资源或开发服务。音频可离线使用。

持久化边界：本轮只做基础工程的启动与可交互编辑，明确标识 NBS 文件读写、MIDI 导入、自动编曲和正式发布流程尚未接入；不放置假装已能保存 NBS 的按钮。先保证窗口和共享状态可维护，随后独立实现格式模块。

验证：状态命令的有意义单元测试；类型检查；生产构建；真实 Electron 进程测试主 / 子窗口、共享更新、音色仅在编辑器出现、关闭重开保留数据、最小化和恢复。产出 Windows 可运行目录和启动说明；不宣称 macOS / Linux 已测试。
