## 明确属于我们设计的部分

图层同步率、音域距离、候选小节长度、动态规划存储/引用开销、变化阈值、复杂度预算，都是可调整的首版参数。并无公开指南证明某个数值能普遍恢复正确乐句。Beta 只输出可编辑的结构建议，不标定主歌/副歌，不自动合并近似变奏，不对音符做生成式补写。

后续改进应以真实作品的人工分组/切句反馈和事件完整性测试为依据：保留算法版本、输入布局和分析报告；升级软件不会悄悄重切已保存的工程。首版基线关注有没有丢音/改音、有没有过度碎片化、完全重复是否真正复用，而非只追求更少 Pattern。

## 首版实现与可调整位置

`src/shared/smartPattern` 是独立于 Electron/React 的纯数据模块。`features.ts` 提取源图层与乐器组成的 lane、发声时间集合、音域，以及每小节的音级分布、24 格节奏特征、音色和密度。24 格只用于评价边界，输出音符仍使用原始 tick。

`grouping.ts` 优先参考去掉末尾编号后的作者名称。通用“图层 1”和单纯乐器名不能证明属于同一声部。无可靠名称时，只对同乐器、不同源层、音域中位数接近、起音高度重合的 lane 作和弦分组。首版将同步率阈值设为 0.72、音域中位数距离上限设为 19 个半音；这两个数都只是工程初值。比较对象是已有组的代表 lane，不做所有音符的两两比较。尚未进行完整的多声部追踪，也没有根据乐器 ID 强制给出鼓/旋律角色。

`segmentation.ts` 使用 1/2/3/4/6/8 小节候选，按相邻小节的音级、节奏、配器、密度和留白变化评价切点。动态规划同时考虑重复频次和结构开销：重复且较长的完整片段可以优于连续单小节，而变化明显的边界降低切分代价。不同声部可独立选择长度。现阶段小节相位仍从原点计算；弱起的事件会保留，但未必得到理想切句。

`index.ts` 仅在同一分组内共享完全相同的 Pattern。签名包含片段长度、图层设置和全部音符属性；散列只查找候选，随后必须比较完整签名。力度变化、移调重复、错位扫弦和微调不同的片段仍是独立对象。整理后再次比较原始触发事件的多重集合；失败则保留原布局。`tailTicks` 另外保留原曲尾音窗口，防止新切点改变 SONG 听感；手动改引用长度/偏移或源 Pattern 长度时取消该扩展。

`profile.ts` 集中保存候选、权重和预算。当前上限为 8192 小节、2048 个 lane、64 组、768 个源 Pattern、9000 个引用和 32 MiB 原始布局备份。超限直接回退，不截断音符，也不偷偷改变分析网格。结果记录 `nbs-structure-1`；未来可替换分组、相位与切句策略，通过新版本和同一完整性基线比较效果。

下一轮最有价值的改进是建立人工标注样本集，衡量声部分组、切点偏差和过度碎片化，再优化弱起/相位、跨小节动机与同音色交织声部。近似重复如要提供，也应作为用户可预览的建议；不能用它覆盖首版的严格共享规则。
